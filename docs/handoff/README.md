# Handoff 파일 규약 — 미완 작업의 재개 지점 (2026-11-13 개정)

- **언제 쓰나:** 작업을 **미완으로 두고 세션을 닫을 때만** 쓴다. 완료 작업의
  인계·머지·배포 상태는 적지 않는다(gh·git·배포 마커에서 읽힌다). 세션 시작 시
  읽어야 하는 문서가 아니다.
- **파일명:** `pr-<번호>-<슬러그>.md`. PR 생성 전이면 `<브랜치슬러그>.md`.
- **소유권:** 만든 세션이 소유한다. 타 세션은 상태 줄 갱신 외 수정 금지.
- **보드:** `PROJECT_MASTER.md` 는 오너가 할 일 목록(1줄·PR 번호 필수)이다.
  이 파일과 자동으로 연결되지 않는다.
- **재개 후:** 이어받아 끝낸 작업의 파일은 `docs/archive/handoff/` 로 옮긴다
  (30일 지난 파일은 일괄 이동 대상 — 삭제 없음).
- **데이터(모드 L):** 이 디렉터리는 README 를 제외하고 git 미추적(로컬 전용)이다.
  git 백업이 없으므로 영속 가치가 있는 결정은 코드·계약 테스트·`docs/agents/` 로
  환원한다. 워크트리 세션은 메인 레포 루트의 `docs/handoff/` 에 쓴다.

## 템플릿

```md
# <제목> (PR #NN · 브랜치 <이름>)

- 상태: 진행중 | PR 대기 | 머지됨·검증 대기 | 블록(<사유>)
- 다음 게이트: <누가> <무엇을>
- 한 줄 정의: <이 작업이 무엇인지 모호함 없이>
- 필독 경로: <파일> — <왜 읽어야 하는지>
- 검증: <수행한 검증과 결과 요약>
- 함정/제약: <다음 세션이 걸려 넘어질 것>
- 미결(오너): <오너만 결정할 수 있는 것>
```
