# 메일 계정 구글 전환 — 오너 절차

> 대상: 오너. 앱 코드는 이미 구글에 붙을 준비가 끝났고, **여기 적힌 두 가지는 사람이 직접
> 해야 하는 단계**다(에이전트가 비밀번호를 발급하거나 입력하지 않는다 — P0).
>
> 전환 전에는 앱이 다음메일(Daum)에 붙어 있었다. 세 기능이 **같은 계정 하나**를 쓴다:
> ①정산 화면의 세금계산서 「메일함에서 확인」 ②브랜드사에 발주서 보내기
> ③브랜드사 회신에서 송장번호 긁어오기.
>
> ⚠️ **구글 화면의 메뉴 경로는 이 문서가 적지 않는다.** 에이전트가 그 화면을 직접 열어 보지
> 않았고, 보지 않은 제3자 UI 경로를 적으면 틀린 길로 안내하게 된다(P4). 그래서 아래는
> **무엇을 이루어야 하는지**만 적는다 — 화면에서 그 항목을 찾는 것은 오너 몫이고, 구글이
> 화면을 바꿔도 이 문서는 낡지 않는다.

## 0. 무엇이 이미 되어 있는가

- `ygrd.kr` 수신은 Cloudflare Email Routing 이 받아 Gmail 로 넘긴다(2026-08-23).
- 세금계산서 메일은 Gmail 의 **`세금계산서` 라벨**로 분류되도록 오너가 설정해 뒀다
  (2026-09-01). 앱은 이 이름의 라벨을 우선으로 찾는다.
  - ⚠️ **라벨 이름을 바꾸거나 다른 라벨 밑으로 넣으면** 정확 일치가 깨진다. 그래도 이름에
    `계산서` 가 남아 있으면 앱이 부분 일치로 찾아내지만, 그런 라벨이 둘 이상이면 어느
    쪽을 볼지 장담할 수 없다. **이름은 그대로 두는 편이 안전하다.**
- **서버 주소는 계정 주소가 정한다.** 앱은 `SMTP_USER` 가 다음메일 계정이면 다음메일 서버로,
  그 외에는 구글 서버로 붙는다. 그래서 **배포와 `.env` 교체의 순서를 신경 쓰지 않아도 된다** —
  계정을 바꾸는 순간이 곧 전환 시점이고, 그 전까지는 지금 그대로 다음메일로 동작한다.

## 1. 앱 비밀번호 발급 — 이것이 없으면 세 기능 모두 멈춘다

구글은 2025-03-14 부로 **일반 비밀번호로는 메일 프로그램 접속을 받지 않는다.** 그래서
계정 비밀번호가 아니라 **앱 비밀번호**(16자리)가 필요하다.

1. 앱이 읽을 구글 계정으로 로그인한다(어느 계정인지는 오너가 안다 — 이 문서에 개인 계정
   주소를 적지 않는다, P0).
2. 그 계정의 **2단계 인증을 켠다.** 켜져 있지 않으면 앱 비밀번호를 만들 수 없다.
3. 그 계정에서 **앱 비밀번호를 하나 발급한다**(이름은 아무거나, 예 `wagcrm`).
   찾는 법은 구글 계정 도움말에서 「앱 비밀번호」를 검색하면 **현재 화면 기준** 절차가 나온다.
4. 나온 16자리를 셀프호스트 `.env` 에 넣는다:
   - `SMTP_USER` = 그 구글 계정 주소
   - `SMTP_PASS` = 발급받은 16자리 (띄어쓰기 없이)

⚠️ 앱 비밀번호는 **발급 화면을 닫으면 다시 못 본다.** 잃어버리면 지우고 새로 만든다.

## 2. 발신 주소 등록 — 안 하면 발신인이 조용히 바뀐다

발주서는 `info@ygrd.kr` 로 나가기로 했다(오너 결정 2026-09-01). 그런데 구글은
**계정에 등록·인증된 주소로만** 보내 준다.

⚠️ **등록하지 않아도 메일은 나간다.** 대신 구글이 발신인을 **로그인 계정 주소로 말없이
바꿔서** 보낸다 — 오류가 아니라 치환이라 앱 로그에는 성공으로 남고, 브랜드사 화면에서만
드러난다.

1. Gmail 설정에서 **보내는 주소로 `info@ygrd.kr` 을 추가**한다(구글 도움말에서 「다른 주소로
   메일 보내기」를 검색하면 현재 화면 기준 절차가 나온다).
2. 구글이 그 주소로 **확인 코드**를 보낸다. Cloudflare 가 이미 Gmail 로 넘겨주고 있으므로
   같은 받은편지함에서 받을 수 있다. 코드를 넣고 확인을 마친다.
3. 셀프호스트 `.env` 에 `SMTP_FROM_EMAIL=info@ygrd.kr` 을 넣는다.
   - 비워 두면 배포 점검기가 **경고**를 낸다(`npm run env:check:selfhost`). 비면 메일함
     계정 주소가 브랜드사 화면에 그대로 나가기 때문이다.
   - 1번 등록을 안 한 채 이 값만 넣으면 **경고 없이 잘못 나간다**(구글이 발신인을 말없이
     로그인 계정 주소로 바꾼다). 점검기는 등록 여부를 볼 수 없다.

ℹ️ 등록을 마쳐도 받는 사람 화면에 **「gmail.com을 통해」** 같은 꼬리표가 붙을 수 있다.
이건 구글이 붙이는 것이라 없앨 수 없다(없애려면 별도 발송 서비스가 필요한데, 그건 이
전환의 범위 밖이다). `ygrd.kr` 의 메일 인증 정책이 `p=reject` 가 아니라 `p=none` 이므로
**반송되지는 않는다**(2026-09-01 실측).

## 3. 확인

`.env` 를 고쳤으면 앱을 다시 띄운 뒤 화면에서 확인한다.

- **수신(①)**: 정산 화면에서 세무처리 창을 열고 「메일함에서 확인」을 누른다.
  「메일 서버(IMAP) 연동 정보가 설정되어 있지 않습니다」가 뜨면 1번이 안 된 것이고,
  인증 오류가 뜨면 일반 비밀번호를 넣은 것이다(앱 비밀번호여야 한다).
- **발신(②)**: 실제 브랜드사로 시험 발송하지 말 것. 확인은 다음 실제 발주 때 하고,
  그때 발신 주소가 `info@ygrd.kr` 인지 본다(본인에게 숨은참조 사본이 가므로 그걸로
  확인할 수 있다).
- **송장 회신(③)**: 발주 대시보드의 송장 회신 가져오기. 받은편지함 → 라벨 →
  전체보관함 차례로 훑는다.

## 되돌리기

옛 계정 정보를 `.env` 에 다시 넣으면 서버도 자동으로 따라 돌아간다 — 코드 수정도,
호스트 설정도 필요 없다.

```
SMTP_USER=<옛 다음메일 계정>
SMTP_PASS=<옛 다음메일 비밀번호>
```
